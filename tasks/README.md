# 《菜刀闯江湖》1.0 原子任务执行说明

本目录把 `docs/PLAN_v2.md` 拆成可顺序执行的代码任务。任务以用户指定的 `gpt 5.6-luna` 为执行目标，但不依赖未公开或模型专属能力；任何具备仓库读写、终端和测试能力的编码代理都可按相同契约执行。

## 执行顺序

1. 从 `tasks/INDEX.md` 选择第一个依赖全部完成、状态仍为 `pending` 的任务。
2. 完整读取本文件、该任务文件、任务列出的计划章节与现有相关代码。
3. 先复现当前基线，再做任务范围内的最小必要修改。
4. 运行任务列出的验证命令；不得用 fallback、跳过测试或弱化断言掩盖失败。
5. 仅当验收项全部满足时，将任务文件 frontmatter 的 `status` 改为 `done`，并勾选 `INDEX.md` 对应项。
6. 若同一阻塞条件连续出现三次，停止修改，将状态改为 `blocked`，在任务底部记录已知事实、三次尝试和下一项所需输入。

## 全局约束

- 以 `docs/PLAN_v2.md` 为产品和架构真相源；任务文件只缩小范围，不覆盖计划约束。
- 保持 React 19、TypeScript、Vite、Zustand、Zod；没有任务明确要求时不增加依赖。
- 纯前端、离线优先、GitHub Pages 子路径可用；运行时不得请求第三方资源。
- 不读取或写入 `.env*`、Token、Cookie、私钥等敏感数据。
- 不修改与当前任务无关的用户改动，不执行 `git reset --hard`、强推或不可恢复删除。
- 领域逻辑不得写进 React 组件；任务、奖励和分支使用数据配置与 `Condition/Effect`。
- AI 预留仅允许 `LocalTextProvider`；1.0 不实现远程模型调用或凭据 UI。
- 所有随机结果走可保存的确定性 RNG；测试不得依赖 `Math.random()`。
- 桌面与移动端功能一致；交互目标不小于 44px，减少动态效果必须有静态替代。
- 不新增占位按钮、“敬请期待”、远程图片或无法完成的任务入口。

## 每个任务的规模上限

- 只解决一个领域能力或一个章节切片。
- 优先修改 1–6 个生产文件及对应测试；超过范围时先拆分，不顺带完成后续任务。
- 单次任务不得同时进行架构迁移、批量内容生产和发布配置三类工作。
- 新代码文件建议低于 800 行，React 组件优先低于 300 行；大型章节配置按场景/任务拆分。

## 通用验证

任务文件的命令是最低要求。若脚本已在前置任务中建立，完成生产代码任务通常还应运行：

```powershell
pnpm lint
pnpm test
pnpm build
```

涉及页面流程时追加：

```powershell
pnpm test:e2e
```

涉及内容数据时追加：

```powershell
pnpm content:validate
```

## 完成回报格式

- 改动文件：列出实际文件。
- 实现结果：只描述本任务范围。
- 验证结果：逐条列出命令与通过/失败。
- 风险或未验证项：必须客观说明；没有则写“无”。
