# 《菜刀闯江湖》Demo 精简实施计划

## Summary

- 将 `docs/PLAN.md` 替换为本计划，从当前仅有规划文档的目录初始化 `React + TypeScript + Vite + Zustand + Zod` 项目。
- 核心路径控制在 15–25 分钟：创角 → 老头教学 → 挑战白大侠 → 奖励成长 → 返回村庄 → 刷新后继续。
- “王大娘找猫”为可选支线，目标时长 5–10 分钟。
- 首版只制作小愚村、一场 Boss 战和一个存档槽；不实现随机战斗事件、完整成就系统或分享卡片。
- 完成桌面 16:9 与小于 768px 的手机竖屏布局，最后发布至公开 GitHub Pages。

## Scope and Humor Priorities

### Must，发布阻塞项

- 可改名角色和莽夫、机灵鬼、厚脸皮三种轻量天赋。
- 主线、找猫三分支、白大侠阶段战斗、奖励、装备和自动存档完整闭环。
- 创角、快速跳过、战败时的旁白吐槽；同一旁白池未轮完前不重复，触发冷却 8 秒。
- 基础搞笑技能：菜刀乱舞、嘴遁、装死；白大侠使用降龙十巴掌和会把自己转晕的无敌风火轮。
- 战斗日志短评、滑稽失败评价和原地重试，失败不回滚剧情。
- 所有对话节点都有正常推进路径；迷惑分支最多绕行两个节点便返回主线。
- IndexedDB 自动保存、继续游戏、导入导出及存档不可用提示。

### Should，Must 全部通过后实现，本次仍纳入交付

- 四个行为称号：话痨克星、猫爪试炼者、挨打不还手、菜刀新秀；属性奖励保持在 1–2 点或 1%。
- NPC 烦躁递进最多五次，第五次给一文钱“封口费”，之后不继续追加状态。
- 老板键支持 `Esc` 和角落按钮；进入采购表伪装时暂停战斗、计时器和音频，恢复后继续原状态。
- 受击、暴击、嘲讽三类漫画表情气泡。
- 过期大还丹和二锅头两个搞笑道具。
- 精简图鉴页显示已遇 NPC、技能和称号，不扩展为完整收集系统。

### Could，明确不进入本次实现

- 15 秒闲置自言自语、5% 突发战斗事件。
- 完整成就页、战报截图分享、多个采购表皮肤。
- 更多地图、Boss、装备强化、随机奇遇和结局系统。
- 仅保留数据驱动的自然扩展能力，不提前编写未使用的系统抽象。

### 幽默安全阀

- 战斗负面效果最多持续两回合，并在日志和状态区显示解除条件。
- 二锅头调整为攻击 `+25%`、命中 `-15%`；铁头功自伤不超过最大生命的 `8%`。
- 场景内搞笑伤害不能让玩家生命降到 1 以下。
- 迷惑选择可少拿奖励或多看对白，但不得锁死主线。
- 战斗失败只产生评价和重试，不扣装备、银两或任务进度。
- 主线对白总量控制在约 35–45 个短节点，白大侠战斗正常为 4–7 回合。

## Implementation Changes

### 游戏架构与数据

- 使用 `ScreenId` 管理 `menu / creation / jianghu / battle / bossCover`，不引入客户端路由。
- Zustand 只保存运行状态和领域动作；剧情、NPC、任务、物品、技能、敌人与文案全部使用 TypeScript 数据配置。
- 定义 `GameState`、`PlayerState`、`DialogueNode`、`QuestState`、`BattleState`、`Skill`、`Item`、`Enemy`、`TitleDefinition` 和 `GameSaveV1`。
- `DialogueNode` 包含 `humorTag`、`options`、`rewardOnSelect`、`narratorTrigger`；选项明确标记 `progress` 或 `humorDetour`。
- 使用领域事件联合类型记录 `npc_clicked`、`cat_grabbed`、`battle_won`、`damage_taken` 等行为；称号配置通过简单事件计数匹配解锁。
- 战斗接受可注入且可持久化的 RNG 状态，确保测试和刷新后的行为可复现。
- Zod 校验导入存档和关键内容数据；版本不兼容时拒绝覆盖当前存档并说明原因。

### 界面与交互

- 主菜单高保真复现原图的水墨山景、题字、角色和木牌按钮。
- 小愚村使用背景、角色、NPC、猫、建筑和 UI 的分层 DOM；热点使用独立按钮及 `data-hotspot`，视觉图层不承担点击判定。
- 桌面布局保持左右信息栏、中央场景、右侧操作入口和底部技能栏。
- 小于 768px 切换竖屏布局：紧凑角色状态、任务/传闻标签、约 45vh 场景、底部固定操作区和 2×2 技能栏。
- CSS Transform 和 Web Animations 处理呼吸、攻击、受击及气泡；“减少动态效果”关闭非必要移动并缩短状态动画。
- 对话和关键战斗状态通过中文 `aria-live="polite"` 播报；按钮具备键盘焦点、禁用和按下状态，触摸区域不小于 44px。

### 素材与性能

统一 ImageGen 模板：

> 中国水墨卡通网页游戏美术，Q 版武侠，手绘墨线，低饱和青绿、土黄与朱红，宣纸颗粒，清晰轮廓，无文字、无 UI、无水印；主体 `{subject}`，视角 `{view}`，用途 `{assetType}`。

| 资源 | 数量与目标规格 |
|---|---|
| 菜单、小愚村背景 | 2 张，1920×1080 WebP，每张不超过 550 KB |
| 主角、老头、王大娘、白大侠、猫 | 5 个透明 WebP，长边 768px，每个不超过 250 KB |
| 木牌、宣纸、技能槽纹理 | 3 个可九宫格缩放资源 |
| 技能、道具和状态图标 | 约 12 个，256×256 WebP，每个不超过 50 KB |
| 漫画表情 | 优先使用 CSS/SVG，不额外生成大图 |

- 所有中文文字由 DOM 渲染；图片中不生成标题或按钮文字。
- `Ma Shan Zheng` 仅用于标题并进行字符子集化，正文采用系统楷体/宋体回退。
- 提供 `pnpm assets:optimize`，通过 Sharp 统一压缩、尺寸和透明通道；构建检查单文件及首屏资源预算。
- 首屏目标压缩传输量不超过 5 MB；非当前面板图片懒加载，场景常驻 DOM 节点控制在约 200 个以内。
- Web Audio 在首次用户手势后解锁；设置包含总静音、BGM、SFX 和搞笑音效四级控制，同时播放音效不超过四个。

## Implementation Order and Verification

1. 初始化工程、设计令牌、数据类型和 ScreenId；先完成无幽默的创角 → 对话 → 战斗 → 奖励主流程。
2. 完成确定性战斗、IndexedDB 单槽存档、导入导出和刷新恢复。
3. 加入找猫支线及三种选择，验证所有选项都能回到可推进状态。
4. 加入 Must 幽默层，并分别验证旁白冷却、搞笑技能、失败安全阀和战斗日志。
5. 加入 Should 功能：四个称号、五级烦躁、老板键、漫画气泡和两个道具。
6. 完成桌面与手机布局、字体子集化、资源压缩、音频、无障碍和性能检查。
7. 初始化 Git，创建公开 `caidao-jianghu` 仓库，推送 `main`，启用 GitHub Actions Pages 并验证线上版本。

### Automated Tests

- Vitest 覆盖伤害、暴击、闪避、冷却、阶段机制、奖励幂等和 RNG 恢复。
- 覆盖迷惑分支回归主线、NPC 点击计数、称号解锁、旁白冷却、负面状态到期及老板键暂停。
- 覆盖有效存档、损坏 JSON、版本不匹配和 IndexedDB 不可用状态。
- Playwright 在 1440×900 和 412×915 下跑通主线及找猫三种选择。
- Playwright 验证快速跳过吐槽、老板键切换恢复、战败重试、刷新继续、竖屏无横向溢出和资源子路径。
- 使用固定 `/caidao-jianghu/` Vite `base`，所有运行时资源通过 `import.meta.env.BASE_URL` 构造。
- 发布前必须通过 `pnpm lint`、`pnpm test`、`pnpm build` 和 Playwright；Pages 线上再次验证首页、WebP、字体、继续游戏及移动端布局。

## Assumptions

- 首版只制作小愚村和一场白大侠 Boss 战，不扩展到三地图、25 个任务或完整结局。
- 游戏正式名称使用"菜刀闯江湖"，"小虾米闯江湖"仅作为角色或章节文案。
- 整体叙事以逗趣、反套路武侠为主，避免现实政治、低俗辱骂和针对真实群体的笑料。
- GitHub 仓库公开，默认名称为 `caidao-jianghu`；线上发布依赖用户已有或现场完成的 GitHub 浏览器登录。
- **最小代码实现原则**：以尽可能少的代码量完成计划中的所有功能，具体策略包括：
  - 优先用数据驱动（JSON/TS 配置表）代替硬编码逻辑，同一套渲染引擎消费不同数据即可产出不同内容。
  - 复用组件：对话面板、弹窗、列表、卡片等抽象为通用组件，通过 props/配置区分用途，杜绝复制粘贴。
  - 合并相似系统：称号、成就、图鉴共用同一套"条件触发 → 解锁 → 展示"框架；道具、装备、技能共用同一套背包渲染逻辑。
  - 战斗、对话、旁白等文案全部外置为数据文件，逻辑层只做调度，不内联文案字符串。
  - 避免引入不必要的第三方库，能用原生 API（Web Audio、Canvas、CSS 动画）实现的不额外装包。
  - 单文件不超过 300 行；超出时按职责拆分，但不过度拆分导致文件碎片化。
  - 所有配置参数（阈值、冷却时间、概率、容量上限等）必须在文件顶部集中声明，不得散落在函数体内。
  - 每个配置参数必须附带清晰的中文注释，说明含义、单位和取值范围。
  - 硬编码的字符串（提示文案、键名等）和魔法数字必须提取到顶部配置区域或独立数据文件，函数体内不允许出现无注释的裸字面量。
